# Governance backend

SF-5 T005 implements R-governance-002 and R-identity-004 through D-4, D-6 and D-16. Its executable acceptance evidence is named TC-SF5-GOVERNANCE-002 and TC-SF5-IDENTITY-012/013 in the colocated tests. Cross-entry consistency remains T021; host assembly remains T020.

`createGovernanceServices` accepts a non-owner application pool, trusted identity authorization callbacks and an independently retained `AuditCheckpointStore`. Register its service factory with the host. There are no authorization, database or checkpoint fallbacks. Pass the actual secret values to its redactor, including refreshed values after credential rotation. Production identity callbacks arrive through T006; unit-test callbacks do not constitute real identity integration.

`createFileCheckpointStore(directory)` is a concrete checkpoint adapter: provide an existing mounted directory outside the audit database's retention boundary, persist it across restarts and restrict its ownership to the service. Publication fails if that mount root is missing; it does not silently recreate retention storage. It publishes immutable sequence/hash files atomically and retains the greatest sequence despite concurrent or out-of-order publication. Missing or corrupt retained evidence fails verification. It detects database-only truncation; simultaneous loss or compromise of both stores is outside that guarantee.

For each explicitly authorized organization, `createTenantForwarder(orgId, options)` registers governance's tenant-bound owner port and audit consumer. Register other owner ports and consumers for that same organization before starting it. The host owns tenant discovery, polling lifecycle, shutdown and closing the pool; the forwarder does not enumerate schemas or bypass tenant isolation. `createGovernancePlugin(forwarder)` exposes that registry to plugin extensions. `stop()` drains the current batch before the host closes storage. The supplied error callback receives sanitized errors; other hosts using the generic event forwarder must apply their own redaction before logging.

Consumer receipts and business effects commit together inside the owning repository transaction. External checkpoint publication follows commit. A failed publication leaves delivery unacknowledged; redelivery repairs the checkpoint without duplicating the audit event. Unrouted messages retry, and polling delivers without NOTIFY. See [storage guarantees](migrations/README.md) and [application boundaries](src/application/README.md).
