# GitHub adapter

T009 supplies the gateway GitHub protocol implementation and CORE action/cursor persistence. `createGitHubModule` registers the adapter through `connectAdapters`; `createConnectActionState` uses CORE's non-owner pool. The gateway receives typed authenticated state ports, never a database. T020 binds actual mTLS transports, identity/data/audit services and configured routes; fixtures are not a deployed host. T017 owns exact specification file publishing and domain confirmation, T022 real process-kill recovery, T024 dedicated real GitHub evidence.

`createGitHubCredentials` uses a T008 current-envelope secret callback with JSON `{privateKey, webhookSecret}`, signs an RS256 App JWT and requests a short-lived token restricted to the configured immutable repository ID. Tokens are acquired per call, never stored in CORE. Only the trusted configuration can enable a loopback HTTP fixture origin; default requests use GitHub HTTPS. The immutable App user ID is required to distinguish an authentic action marker from copied user text. No approve/merge endpoint or arbitrary URL fetch exists.

Webhook signatures cover copied original bytes; durable receipt precedes ACK. Polling runs every 15 minutes and immediately on start/recovery. It overlaps watermarks, restarts unstable pagination after failure, and advances the high watermark only after all pages. All PRs are checked for review changes independently of issue timestamps. Current PR/head fields are reread after related pages, but GitHub does not offer an atomic snapshot across reviews/comments; T017 must reread before gate decisions. Observation time is sampled after the final successful current-object read, not at request start; this is not a cross-host global order. Raw review IDs, commit IDs, dismissed states, closed and merged facts remain separate from domain approval. Unresolved immutable-ID associations are recorded by identity and can be replayed with a new association-version event, preserving the same logical source identity.

A missing object (including ambiguous 404/410), permission failure or failed page rejects the observation, retains the watermark and invokes the mandatory trusted rejection-audit sink. It is not silently marked synchronized or guessed to be deleted; downstream state/confirmation must remain pending until current facts are obtainable or a human resolves access/deletion. The sink must not assign unverified payload actors or organizations to an audit tenant. External text/links remain untrusted immutable references and are never fetched as arbitrary URLs.

Actions register before sending and persist `unknown` before the external call. Concurrent delivery uses a CORE lease. Unknown outcomes query the exact App-owned marker or deterministic PR branch; absence alone never licenses another send. Before an actual POST/PATCH starts, temporary reads or token failures preserve a fresh pending action for retry. After a write starts, an uncertain response remains unknown. Rate rejection records a retry time (at least one minute when GitHub supplies no usable deadline); an unknown historical effect remains query-only. Permission or definite write rejection fails a fresh action, while denial of a recovery query cannot prove a historical effect failed and preserves unknown. The mandatory outcome-audit port records fixed safe reasons for downstream human handling. Safe classifications cross the T008 credential callback as controlled results, so secret-provider error sanitization cannot erase rate/permission semantics. Remote success followed by local commit failure is recovered by querying the same effect. This does not promise atomic cancellation of in-flight external requests. Comment updates check the expected old body hash before sending; this is not a cross-system lock against a simultaneous human edit. Specification branch mutations are reserved to T017 and never inferred from an arbitrary action body.
