# CONNECT state and gateway components

T008 exports two factories. `createConnectCore` requires the non-owner application pool, current authorization adapter and durable governance audit port. It registers `connectStateServiceRef` and exposes tenant-bound outbox ports for the existing platform dispatcher. Only CORE owns connect tables. The existing status plugin remains compatible; T020 installs the real host composition.

`createConnectGateway` has no database argument or repository. Its trusted provider verifier consumes original bytes and headers and binds installation ownership; the GitHub HMAC implementation and polling/action recovery belong to T009. It returns an ACK only after the CORE client returns a validated persisted receipt. Receiving a gateway event does not authorize its external author to create a work or approve a gate.

Use `createConnectInternalServer` and `createConnectInternalClient` with separate certificates and a trusted CA. Both verify the expected service DNS identity. The server obtains peer identity from the TLS socket. Its mandatory `resolveContext` must resolve current persisted actor/authorization for that authenticated peer and operation, not echo user-supplied JSON. The server requires a trusted `recordRejection` security-audit sink for malformed requests, denied resolution/operations, and TLS client errors. It receives only a reason enum and an authenticated configured service name where known; rejected bodies cannot choose an audit tenant. Sink failure rejects newly entering requests until restart; it is not an atomic cancellation of operations already in flight. T020 supplies the real deployment audit sink; a component fixture is not evidence of deployed host auditing. CORE independently authorizes the actual target. Internal operation names map to the existing `integration.manage` permission, not new permission points. `createConnectAuthority` delegates to current identity authorization. `createManagedContextResolver` binds the authenticated peer and exact target to a host-configured real management member, preserves service client/source in audit, and rechecks current role/revocation. It never promotes the external event author or grants a service implicit administrator rights. Host binding and real deployment are T020/T022, not supplied by a permissive test fixture.

Gateway master keys come from an external Secret via `MasterKeySource`; no key is persisted by CORE. Each envelope has an independent random data key wrapped with AES-256-GCM, authenticated tenant/integration/key/credential versions, and distinct random nonces. Queries return ciphertext only. Trusted outbound adapters use a scoped buffer which is zeroed after consumption; they must never return or log it. Rotation validates a new credential first and atomically compares the previous credential version before switching the active envelope. Each new use fetches the current active version; already-started external requests cannot be retroactively revoked. Keep a retired master key only as long as its still-valid encrypted versions need it; unavailable keys fail closed.

Outbox events use the plugin's own transaction and schema. Claims use row locks and leases; ACK/retry requires the current unexpired lease. Platform polling is mandatory and does not rely on notification delivery. Inbox delivery identity conflicts fail rather than overwrite accepted content. Accepted receipts survive restart. Work/gate state is not writable through this component. Cursor/action/discussion tables reserve the approved durable domain model for T009; this task does not pretend to implement external action recovery.
