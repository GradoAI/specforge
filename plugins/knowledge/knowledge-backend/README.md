# Project context

T007 exposes `createKnowledgeServices` and versioned PostgreSQL repositories. The host supplies an application-role pool, authorized immutable repository-file reader, current authorization, identity member resolution, environment service, and durable governance audit. The source reader must enforce the project/repository association and return the requested full commit; it must not resolve a moving branch as that commit. T020 owns host assembly. No adapter receives permission to read another plugin's schema.

The database caches parsed `fasrun.yaml` and optional `Fasfile` by organization/repository/commit. New work reads the current organization rule and workflow catalog, selects the configured template, and returns the existing `ProjectContext` version fields. Read existing work with `readProject(..., { repositoryId, baseCommit, pin })`; `selectWorkflow` always supplies that pin. A new work item on the same commit can see newer catalog versions. Existing work requires every pinned version and the exact captured content hash; missing or changed versions fail closed. Catalog changes append a new version; they never overwrite an existing one.

Environment capabilities come exclusively from the environment reference inside the pinned organization rule. `agent.commands` and approved capabilities use exact command identifiers: this layer does not interpret shell equivalence or authorize execution. The default environment allows no command. Constraints intersect capabilities, union mandatory checks and protected paths, and retain the stricter coverage/quarantine requirements. Incomparable or explicitly weaker declarations are rejected. Reviewer identifiers are resolved through the injected current-organization identity port on every read, including cached reads.

Reads persist an allowed access intent before accessing source/cache/catalog data and recheck authorization before returning. Both initial and final denials persist a denied event; audit failure prevents data return. Provider errors cross the public service boundary as fixed safe messages. The host must bind these ports to trusted identity/governance services, rather than deriving decisions from caller-supplied booleans or capabilities.

Provision `knowledgeBaseData(orgId, actorId)` through the existing owner-role migration runner for explicitly provisioned tenants. Defaults include small-defect (requirements only), standard-defect, and feature (requirements/design/tasks) workflows, eight-hour answers, twenty-four-hour reviews, three replans, and the M1 `spec_confirmed` terminal state. Customizations append versioned rows; repeated provisioning preserves existing rows. IDs are stable per tenant and definition version.

`TC-SF5-SPEC-008` unit tests exercise constraint and permission boundaries using controlled ports. PostgreSQL integration tests exercise the real migrations, application-role RLS, immutable cache, concurrent capture, restart, pinned version reads and repeatable base data. Their controlled source/identity/environment/audit ports are contract fixtures, not evidence of real external integration. Run `pnpm --filter @fasrun/plugin-knowledge-backend test` for both projects with coverage; `exec vitest run --project unit` is the isolated unit entry. Colima requires the existing local container environment variables to be passed directly to Vitest when Turborepo removes them.
