# Orchestration data references

T010 provides immutable JSON references and a content-addressed local PV adapter. `createDataServices` from orchestration-backend binds an orchestration-owned pool, a dedicated private content directory, current identity authorization, governance policy/audit, trusted producer attestations and current human confirmation evidence. T020 connects these ports to the real control-plane composition; the status-only host does not instantiate a data store automatically.

`register` canonicalizes JSON and labels, writes and fsyncs a temporary content object, atomically publishes without overwriting an existing address, verifies the content, then commits the immutable index and audit outbox together. The version hashes content digest plus normalized labels; source, trust, read scope, exclusions and confirmation all participate. Reordering set-valued labels does not create a new version. A failed index transaction may leave an unreferenced file for operator-controlled retention; it returns no successful reference. There is no automatic orphan deletion that could remove another concurrent writer's content.

All public operations require an authenticated `OperationContext`. Human members use current identity roles without needing to initiate a work item first; an existing authorization ID remains attached and must pass current revocation, subject and scope checks. Agent actors require their delegated authorization ID. Identity's owner-bound `authorize` adapter must re-read current member/role/scope and the persisted authorization/revocation; the data service never interprets a request flag as authorization. Reads use the immutable stored metadata, check current permissions and policy, persist access intent before loading the value and recheck before returning. Errors do not include content, disk paths or underlying exception messages. Mutation audit events use the orchestration outbox and the existing `governance.audit.requested` consumer. Independent owner resolvers receive a URI and trusted context; their returned labels and canonical content/version must match. No plugin gets another plugin's SQL handle.

Trust is not selected by an input label. Agent actors and agent/external producers always generate untrusted data. A system/trusted-source result requires the host's `trustedProducer` attestation for the exact output digest and normalized labels, current caller/call and complete input-reference list; a registered name alone is insufficient. Any untrusted input forces untrusted output. Read scope may only narrow; exclusions are unioned; changing input classification is rejected. The registered producer must supply the complete actual input set; T011/T014 bind that set from the recorded call/step, never agent-generated metadata. The component does not infer hidden information flows from arbitrary bytes.

`confirm` requires a human actor and the trusted review port's current head, original reference, confirmer, basis and approved permission. Reads require current `work.view`; confirmation rechecks the approved review permission against current identity before creating a new version with the same content and restrictions. Neither reading nor confirming grants or additionally requires `work.create`. A caller-supplied head or statement that a review passed is not confirmation evidence. T017/T020 supply current external review facts; this component does not offer an agent approval endpoint.

`outbound` resolves and checks all references, rechecks destination policy and exclusions, persists intent and rechecks authorization before invoking the effect callback. Destination visibility must come from the trusted governance/channel adapter, not a caller boolean. A refused call has no callback effect; independent callers can continue. The plan interpreter's dependent-step scheduling belongs to T014. HTTP/MCP transport assembly and combination checks belong to T018/T021; component results retain full reference labels during JSON serialization.

The PV directory is service-owned and must not be writable by untrusted local processes. Files are immutable at the API boundary, verified by digest on read, and opened without following a terminal symlink. This is not a sandbox against arbitrary privileged filesystem writes. Identity and orchestration own separate transactions: checks are current at each operation boundary, not a distributed lock against a revocation committed after the final check.

Tests use real PostgreSQL, non-owner RLS connections and real filesystem publication. Identity, policy, producer/review facts and outbound effects are explicitly controlled component ports; real Keycloak/GitHub and full-host stage evidence remains separate. No test uses these controlled ports as proof of full M1 acceptance.
