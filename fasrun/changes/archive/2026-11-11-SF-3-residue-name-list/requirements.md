# SF-3 R-platform-018 旧名清单移入残留检查配置

## 目标
按 #11 中需求评审人的决定，现行规格不再逐字列出被禁止的旧名：R-platform-018 改为引用残留检查配置中的旧名清单，旧名只在该配置文件中出现一次。这样现行规格本身不会被残留检查命中，也不再需要 #16 为这条需求加入的跳过。

## 范围
- 做：
  - 修改 R-platform-018：需求正文与 S1 不再列出旧名，改为按残留检查配置中的旧名清单检查；
  - 旧名清单与例外写在 `tools/scripts/old-names.yaml` 中；
  - 例外为该配置文件、`GradoAI/sf-optio` 与 SF-2 的归档目录。SF-2 的变更目录已归档，不再单列；
  - 残留检查（TC-PLATFORM-054）从配置文件读取旧名与例外，去掉对 R-platform-018 条目的跳过；
  - 交付后归档本变更，把增量合并进 `fasrun/specs/platform/spec.md`。
- 不做：
  - 旧名清单本身的内容不变；
  - R-platform-018 的 S2、S3 不变。

## 用户场景

### US-1 现行规格不被残留检查命中（P1）
作为维护单仓的开发者，我要旧名清单只在残留检查的配置文件中出现，以便现行规格与其他文档不需要为引用旧名而设例外。
独立验证：`fasrun/specs/` 中没有旧名；残留检查没有针对任何需求条目的跳过；在任一受检文件中加入清单中的旧名，残留检查失败并指出文件与行号。
实现它的需求条目：R-platform-018

## 成功标准
- TC-PLATFORM-054 从 `tools/scripts/old-names.yaml` 读取旧名与例外后通过，例外只有该配置文件、`GradoAI/sf-optio` 与 SF-2 的归档目录。
- 现行规格与本变更目录中没有旧名。
