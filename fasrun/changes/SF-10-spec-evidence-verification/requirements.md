## 归属与不变边界

- 同根因一个修复归属，原范围内优先原开放PR；原PR已合并可以有独立修复PR，但不重复已有规范决策。是否越界仍须按实际差异判断，不是任意改代码的许可。
- 已归档能力的小维护以活跃变更引用现行要求、说明范围与保留验收；没有新业务语义不编造新需求、不强制空层，也不重写归档。复杂维护仍按分层工作处理。
- 任务定义、依赖、范围和验收为规范；checkbox、阶段、PR/运行链接及meta状态为事实投影。每批及时对账，在原入口说明待入库项及同步承载点；相关交付/收尾PR或批量快照均可，不以快照待审阻断已满足真实依赖的任务，不无限拖到归档。
- “不需要新的规范决定”不等于免人工审查。实际文件提交仍走CODEOWNERS及既定分工；隐藏于证据更新的任务修改必须作为受影响层修订评审，旧HEAD批准不能确认新HEAD。
- PR选择验证尚未交付。未来实现需另按适用层级批准，保持必需检查、覆盖率及失败关闭；不能仅凭本规范跳过当前CI。本次不改.github、Fasfile、保护规则、生产/测试代码，不扩T023或其他任务实现范围。
- 漂移检查的自动化不在本次交付。当前工具只提供已有Markdown结构、引用、覆盖及配置检查，不核实GitHub实时批准/合并，不证明语义一致性或影响图完备。
- #91已合入；#94的真实失败与#92的现有评审继续原归属，不新增前置、不借本次变更追认未验证修复。#17的Colima限制与CLI构建/测试证据分别保留。

## 六个反例验收

六例均是本次**规范文本的一致性与可判定性验收**，不是已实现产品的自动回归；实际工具结果另见 verification.md。

| 编号 | GIVEN / WHEN | 必须得到的结果与拒绝边界 |
| --- | --- | --- |
| CE-1 | 同一已批准维护范围再次失败，根因归属已存在 | 复用原工作与开放PR、追加失败证据，不再新建同症状诊断/规格PR；若新证据超出范围，明确差异并修订受影响层，不能自行扩范围 |
| CE-2 | 已归档能力有不改变业务验收的小维护 | 新最小活跃变更引用现行规范与历史交付，说明具体范围和回归；不改历史归档、不建空设计/tasks、不默认沿用旧任务权限 |
| CE-3 | 只回写实际合入；另一个更新暗改依赖或验收 | 前者是证据投影同步，可在相关PR承载且保留人工审查；后者必须作为任务/相应规范修订，不能借“进度”夹带 |
| CE-4 | meta写approved，但批准对应旧HEAD或尚未合入 | 原始当前事实优先；不得推进后层或依赖任务；新提交依现行评审规则重新确认，不能手改meta解除阻塞 |
| CE-5 | 同一合入批次反复同步、一次失败后又成功 | 更新原入口/已有同步PR，不新建重复工作或逐状态PR；关联合并SHA及事件/attempt，保留失败及成功，不以重跑宣称修复 |
| CE-6 | 影响未知/共享输入未覆盖、计划版本过期或必需任务未完成 | 未来选择器必须回退全量或失败，不能输出空成功；当前仍完整执行现有CI；PR成功不能替代队列/main/每日完整证据 |
