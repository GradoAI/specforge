### US-1 迁移并发验收失败可诊断且资源有界收束

实现它的需求条目：R-platform-008

既有验收要求两个真实 CLI 同时等待迁移 advisory lock；释放父锁后两个进程均成功，迁移应用次数为 0 和 1，数据库目标行只写入一次。维护后保留这些完整断言，不以模拟迁移、减少等待者或跳过测试替代。

精确代码修改范围仅 `apps/fasrun-dev-cli/src/migrate.int.test.ts`，必要测试辅助代码也限定在该文件内；验证用例继续使用 TC-PLATFORM-025，不重编号。不得修改生产迁移执行器、公共 test-utils、构建生命周期、身份矩阵、CI、保护规则或历史归档。发现必须超出此范围的实质缺项时，按既有缺项流程处理。

维护验收：

- 等待者观测失败、子进程提前退出、进程异常及截止超时仍使测试失败。失败路径收集两个子进程的退出码、信号及有限、脱敏的输出摘要，记录锁观测状态和耗时；不输出数据库连接串、凭据、环境变量或未经筛选的错误对象。
- 无论断言成功或失败，均释放父锁并收束两个子进程；需要终止时采用有界终止并等待退出，完成后才关闭连接和删除测试数据库。不能让断言抛出跳过清理，也不能吞错误使门禁成功。
- 锁观测限定本夹具数据库及目标 advisory lock，不能把同实例其他数据库的等待者计入；保持真实双 CLI 并发与只应用一次的完整验证。
- 保留现有 200 次、每次 25ms 的等待观测预算、45 秒 CLI 截止与 60 秒集成测试截止，先进行有界定向观测，不先增加等待预算。若实际耗时证据表明需要调整，另行报告具体依据，不将等待者断言失败自动解释为预算不足。不扩大通用超时，不使用固定 sleep 求绿，不关闭并发或门禁。
- 验证成功路径及提前失败、等待截止、退出清理路径；故障注入限定本文件测试辅助或临时隔离副本，不污染产品。记录实际失败且不重复运行直到绿。
