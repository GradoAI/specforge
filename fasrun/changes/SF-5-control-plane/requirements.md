# SF-5 M1 控制平面核心

## 目标

帆驭 (Fasrun) 让有权限的成员从一张 GitHub 工单进入可追溯的规格流程，经过澄清、自检及独立人工评审，形成已确认的规格版本。交付真实控制平面及完整 TC-CF-001–020 行为，为后续执行提供可信输入。

工作：[SF-5 / #50](https://github.com/fasrun/fasrun/issues/50)。基线：main `548be4d`，M0 已验收；本工作不重复 M0 收尾。本文是待评审的需求层规格；#51 的范围结论已由用户在 2026-11-12 本次协作会话明确确认，见[确认回写](https://github.com/fasrun/fasrun/issues/51#issuecomment-6822909831)及[确认记录](confirmation.md)。该确认不是本需求 PR 的人工批准；任务层合入前不开始实现。

## 范围

- identity：真实 Keycloak 认证与账号关联、技术方案 2.17 全权限矩阵、条件规则、两层准入、不可变授权及本轮审计事件。
- connect：GitHub 仓库接入、工单与 PR/review 事件、持久收件箱、事务发件箱、幂等写回和每 15 分钟对账；内部 mTLS 及凭据隔离。
- orchestration：人工定义的规格前段流程及声明式计划引擎，持久恢复、关卡、校验、缓存与版本、数据引用和可信度、消息、回放、排空升级。第 6 轮资产按当前四层结构重写，不能直接搬入旧实现和旧运行环境。
- spec：规模分类、澄清、按层自检及 PR、领域确认、当前提交确认、版本化 Fasfile；补齐 #17 的 M1 schema 和受保护路径语义。
- entry：M1 工作及规格所需 HTTP/MCP 接口、统一契约/权限/错误、请求幂等与并发控制。
- agent 调用：交付可替换调用契约，专用验证环境的澄清与规格起草允许用可控桩；真实控制平面及 Keycloak/GitHub 接入必须交付并验收。M2 在同一控制平面与调用契约上接续真实节点、执行器和模型调用链，验证真实起草及完整执行闭环。M1 不宣称真实自动起草能力。
- 支撑范围仅限上述闭环需要的组织/项目/成员关联、规则、流程/步骤目录、引用、策略与约束数据；遵守现行表规范、迁移、schema 隔离、RLS 和契约依赖约定。目录的具体归属与数据模型在设计层确定。

不包含 M2 节点派发、真实执行器与沙箱、模型网关、代码 PR 执行或归档闭环；不包含 M3 页面与通知产品；M4 完整客户端注册、MCP 工具分组/长任务、服务账号与预算运营能力不提前实现。完整权限矩阵及执行段的测试覆盖不代表未来业务端点已交付。M1 必须保留接口及引擎边界，不用跳过执行段控制流用例缩小二十项验收。

UC-01 按 M1 截止规格确认的范围取证；UC-01 完整产品用例中的在线机器及进入执行属于后续里程碑。UC-04 验证规格修订、分层确认及旧确认失效，UC-16 验证 GitHub 接入归属与事件/写回。上述终点都不等同于代码交付完成。

## 用户场景

### US-1 成员通过可信身份发起工作（P1）
成员用 Keycloak 身份发起或关联 GitHub 工单，由同一权限规则判定是否受理，避免冒名、跨组织读取和自动候选绕过准入。
独立验证：真实 Keycloak 登录及无效令牌拒绝；未关联身份不受理；14 角色和全部权限点的允许/拒绝矩阵；明确请求与候选模式对照；角色撤销和授权撤销立即影响后续操作。
实现它的需求条目：R-identity-001、R-identity-002、R-identity-003、R-identity-004、R-governance-001、R-governance-002

### US-2 GitHub 消息可靠进入与写回（P1）
项目接入人配置仓库归属，成员在工单上提出请求、补充信息并查看进展；丢 webhook、重复事件或重启不能丢工作或重复创建 PR。
独立验证：不合法签名拒绝、持久受理后恢复、重复/乱序事件、15 分钟对账补漏、远端动作已成功时的写回重试；配置和错误不泄漏凭据。
实现它的需求条目：R-connect-001、R-connect-002、R-connect-003、R-connect-004、R-orchestration-002

### US-3 从工单推进到分层规格确认（P1）
触发人回答具体澄清后，评审人查看独立规格 PR 与自检证据，按层确认当前版本及所涉领域；前层确认并合并后才能进入下一层。
独立验证：较大工作逐层推进，小工作需求层即可；待澄清或自检不合格不提交；旧提交批准、撤销或关闭未合并不放行；确认只形成可信版本，不宣称代码完成。阶段验收在专用环境连接真实 Keycloak/GitHub，澄清与起草 agent 可用可控桩；另列模拟回归证据，不把桩产出宣称为真实自动起草。
实现它的需求条目：R-spec-005、R-spec-006、R-spec-007、R-spec-008、R-spec-009、R-spec-010、R-platform-017、R-orchestration-010、R-orchestration-015

### US-4 控制流故障后可靠恢复（P1）
成员的工作在重启、外部重试和关卡等待中保留状态，不因队列排满错失人工消息；升级后进行中工作仍使用原版本。
独立验证：TC-CF-001–005、012、017–020 按各需求场景验证真实持久化、幂等、时限、消息交接、回放与版本。
实现它的需求条目：R-orchestration-001、R-orchestration-002、R-orchestration-003、R-orchestration-004、R-orchestration-005、R-orchestration-012、R-orchestration-017、R-orchestration-018、R-orchestration-019、R-orchestration-020

### US-5 计划只能依据可信输入推进（P1）
成员能确认计划受授权、预算、规格和人工关卡约束；不可信工单、评论及 agent 输出不能改变控制流或把排除数据发送出去。
独立验证：TC-CF-006–011、013–016 全部覆盖，包括 fast-check、缓存、三次重规划上限、输入可信边界、不可变引用及可信度传播；拒绝计划一步不执行。
实现它的需求条目：R-orchestration-006、R-orchestration-007、R-orchestration-008、R-orchestration-009、R-orchestration-010、R-orchestration-011、R-orchestration-013、R-orchestration-014、R-orchestration-015、R-orchestration-016、R-governance-001、R-governance-002

### US-6 从 HTTP 或 MCP 使用同一控制平面（P1）
成员经客户端创建工作、查询状态与规格、回答澄清或读取授权引用，切换入口不改变权限与数据边界。
独立验证：双入口同契约和同权限，重复创建幂等，过期 ETag 拒绝；多副本无会话粘连，错误可追溯且不泄密，审计显示成员及客户端。
实现它的需求条目：R-entry-001、R-entry-002、R-entry-003、R-entry-004、R-identity-002、R-orchestration-014

## 成功标准

- TC-CF-001–020 按现行语义全部通过；使用真实 DBOS/Postgres。快速集与杀进程/排空升级完整集分别取证，真实模型评测不能替代控制流回归。
- 上述用户场景与全部增量需求有对应测试；一张工单到规格 PR 当前版本确认及合并的证据可串联，包含至少一次澄清和职责分离拒绝。阶段验收在专用验证环境使用真实控制平面、Keycloak/GitHub，澄清和起草 agent 可使用可控桩；明确记录组件、配置版本及真实外部对象链接。
- 真实 Keycloak/GitHub 接入的阶段验收与模拟回归分别取证。真实接入仅使用专用验证环境的授权账号及仓库；日常自动回归的外部异常、重复和乱序使用隔离夹具，不触及真实用户数据。模拟适配器测试不替代真实接入验收；阶段桩起草不等于真实自动起草。
- 保留既有工程、覆盖率、迁移、许可与密钥门槛；每次变更使用已交付 spec validate/check。现行校验器只验证格式及引用，不代替 THEN 可判定性检查。
- 验证记录分别写明本机标准入口、替代方式、PR CI、合并队列和主干的实际结果；#17 Colima/Turbo 环境限制继续保留，旧历史实验不能作为本工作通过证据。
