## ADDED Requirements

### Requirement: R-identity-001 成员认证与唯一账号关联
成员必须经 Keycloak OIDC 认证；会话及令牌须校验有效期、签发方和目标受众，浏览器会话使用 HttpOnly Cookie。外部账号必须关联到唯一成员，不能按显示名或用户名猜测身份；未关联或歧义身份不得产生授权请求，须提示管理员处理。成员停用后不能继续使用原会话发起操作。M1 验证真实 Keycloak 的登录与认证拒绝；登录主题、设备授权命令行和个人访问令牌的完整产品流程留待对应里程碑。
#### Scenario: R-identity-001.S1 真实身份认证
- GIVEN 验证环境的 Keycloak 中有已关联成员，且成员未停用
- WHEN 成员完成 OIDC 登录并请求本人可访问的工作
- THEN 请求识别为该成员；浏览器会话 Cookie 为 HttpOnly；认证事件可查且不含令牌明文
#### Scenario: R-identity-001.S2 无效或停用身份
- GIVEN 请求未登录、令牌已过期、签发方或受众不符，或成员已停用
- WHEN 请求受保护的 HTTP 接口或 MCP 工具
- THEN 请求被拒绝且不发生业务变更，拒绝原因可追溯
#### Scenario: R-identity-001.S3 外部身份不能猜测
- GIVEN GitHub 请求者未关联成员或存在多个关联候选，即使其用户名与某成员相同
- WHEN 处理请求者的指派、提及或评审
- THEN 不据此创建授权工作或确认规格；记录待管理员处理的关联问题

### Requirement: R-identity-002 统一权限矩阵与职责分离
HTTP、MCP、步骤开始和数据读取必须使用同一权限判定。规则包含范围、主体域、权限点和附加检查；上级授权向下继承，各层授权取并集但不跨组织。按技术方案 2.17 的全部权限点和 14 个内置角色验证静态及动态主体域，返回判定与命中规则。agent 不具批准权限，触发人不能独自批准，兼任受项目设置约束。未来业务权限点的规则测试不意味着实现未来业务端点。
#### Scenario: R-identity-002.S1 范围继承与隔离
- GIVEN 成员在一个组织及其团队有不同授权，且另一组织没有授予该成员权限
- WHEN 查询有效权限并分别读取两个组织的工作
- THEN 本组织结果包含适用规则的并集及尚待对象求值的条件；另一组织访问被拒绝，不能通过标识猜测绕过隔离
#### Scenario: R-identity-002.S2 矩阵与动态条件
- GIVEN 14 个内置角色、2.17 全部权限点及触发人、评审人等对象关系的允许和拒绝样例
- WHEN 逐项判定并改变关系或附加条件
- THEN 每项结果符合矩阵与项目兼任设置，能指出命中规则；观察者仅可读，平台管理员不会自动获得专门角色的批准权限
#### Scenario: R-identity-002.S3 不允许自我批准
- GIVEN agent、仅有触发人身份的成员和有相应评审权限的独立成员分别提交确认
- WHEN 判定需求、设计或任务层确认权限
- THEN agent 与没有相应权限的触发人被拒绝；只有满足该层权限和职责分离条件的成员可确认
#### Scenario: R-identity-002.S4 每次检查立即生效
- GIVEN 已登录成员被撤销角色，或工作的授权记录被显式撤销
- WHEN 发起下一次接口、工具、数据读取或步骤操作
- THEN 使用撤销后的权限拒绝越权操作，旧会话及先前成功判定不能绕过检查，拒绝进入审计

### Requirement: R-identity-003 两层受理与不可变授权记录
受理先确定身份、权限与请求强度；有权限人的明确请求可进入工作，推断候选须再经研判并满足接收模式和主动工作规则，bot 只能产生候选。成功受理生成不可变授权记录，包含策略版本、范围、请求强度、命中规则与触发人。工单和评论原文始终是不可信数据，不能成为规划控制流的可信指令。范围扩大重新受理；策略更新通知已有工作，显式撤销立即生效；已结束工作恢复前按现行策略重验。
#### Scenario: R-identity-003.S1 明确请求与授权快照
- GIVEN 已关联且有项目发起权限的成员明确指派工单给 Fasrun
- WHEN 准入判定通过并受理
- THEN 创建一项归属于该成员的工作及内容完整的不可变授权记录；后续策略变化不能改写该历史记录
#### Scenario: R-identity-003.S2 推断候选不能直接启动
- GIVEN 仅提及但没有明确请求的消息或 bot 消息，接收模式为关闭或观察
- WHEN 处理该候选
- THEN 关闭模式不受理工作，观察模式仅记录候选及建议而不自动启动；消息正文不能把自身提升为可信指令
#### Scenario: R-identity-003.S3 自动模式仍须准入
- GIVEN 接收模式为自动且有适用的主动工作规则
- WHEN 候选完成研判
- THEN 只有同时满足权限、规则和研判条件的候选生成工作及引用规则版本的授权记录；bot 不因文本声称获得人的身份或批准权限
#### Scenario: R-identity-003.S4 范围和策略变化
- GIVEN 一项已有授权的工作及一次扩大范围的请求
- WHEN 策略更新、请求扩大范围或尝试恢复已结束工作
- THEN 策略更新通知原工作而不自动撤销；扩大范围另行受理；恢复按现行策略重新校验，不满足时保持未恢复并记录原因

### Requirement: R-identity-004 安全审计与秘密遮蔽
认证、权限拒绝、角色及授权变更、对外动作、数据引用解析和规格确认须形成可追溯的只追加审计事件，关联主体、对象及工作。事件哈希链须使修改或删除可被发现。日志、错误和审计写入前遮蔽令牌、密钥及凭据；无审计权限者不能读取审计。M1 仅验收本轮发生的事件，不宣称未来执行器、插件或正式主机安全验收完成。
#### Scenario: R-identity-004.S1 审计链完整且可验
- GIVEN 一次包含认证、受理、拒绝、授权变更、数据读取、写回及规格确认的流程
- WHEN 查询审计并对副本篡改或删除任一事件后验证
- THEN 原链可验证且各操作可追溯；被修改或删除的链验证失败并指出异常
#### Scenario: R-identity-004.S2 秘密与审计访问隔离
- GIVEN 请求及外部系统异常包含测试令牌或凭据，另有无审计权限的成员
- WHEN 记录错误和审计并尝试读取审计
- THEN 日志、错误和审计不出现秘密明文；无权限读取被拒绝
