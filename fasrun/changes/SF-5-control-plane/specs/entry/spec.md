## ADDED Requirements

### Requirement: R-entry-001 同源契约与稳定接口
M1 的 HTTP 接口和 MCP 工具必须使用插件 common 包中的同一份契约与权限声明，提供发起工作、查询状态及规格、回答澄清、补充指示和按引用读取的能力。HTTP 使用版本化路径，生成 OpenAPI 3.1 描述与 TypeScript 客户端；MCP 使用可流式 HTTP，不依赖内存会话粘连。不能暴露尚未交付的执行或界面能力为可用工具。
#### Scenario: R-entry-001.S1 两个入口相同规则
- GIVEN 同一成员、相同合法和非法参数，经 HTTP 和 MCP 请求同一能力
- WHEN 校验、鉴权并执行请求
- THEN 两入口返回等价的业务结果或拒绝，不因切换入口绕过参数、权限及数据范围检查；描述与实际参数一致
#### Scenario: R-entry-001.S2 无会话粘连
- GIVEN 请求被交替发往两个控制平面副本
- WHEN 成员发起工作后查询状态及回答问题
- THEN 不依赖上一请求所在进程，工作与回答可持续查询，认证仍逐次校验

### Requirement: R-entry-002 幂等与并发更新
创建及触发请求（含回答澄清、补充指示）必须支持 Idempotency-Key，同一主体与相同请求重试返回第一次结果，键与不同内容冲突时明确拒绝。可变资源更新须通过 ETag 和 If-Match 检测冲突；列表使用游标分页。请求入站可以确认已持久受理，但不得把排队或等待人工的工作报告为完成。
#### Scenario: R-entry-002.S1 重复创建与并发冲突
- GIVEN 同一成员重复发送同一创建请求，另有相同键不同内容及过期 ETag 更新
- WHEN 请求经两个入口到达
- THEN 同请求只产生一个工作；冲突内容和过期更新拒绝且不覆盖新状态，返回可识别的冲突原因
#### Scenario: R-entry-002.S2 读取分页与真实状态
- GIVEN 超过单页数量且包含等待输入的工作
- WHEN 按游标读取列表和工作详情
- THEN 在不变数据集中可遍历全部授权可见工作而不重复或越权；等待输入被准确表示，不作为完成返回

#### Scenario: R-entry-002.S3 回答及指示重投不重复推进
- GIVEN 一个澄清回答或可信补充指示已受理但客户端没有收到响应
- WHEN 同一主体以同一键和内容经任一入口重投
- THEN 返回原结果，回答只推进一次、指示只产生一次相应计划版本；同键不同内容被拒绝

### Requirement: R-entry-003 错误与代理来源审计
HTTP 错误必须采用 RFC 9457 问题详情，包含登记的插件错误码及链路标识；MCP 保留等价可识别错误。错误码在 common 契约登记并生成目录，CLI 既有 JSON 信封与退出码保持兼容。经客户端操作必须记录“成员经客户端”的来源；外部文本始终按不可信输入处理，不因 MCP 调用而升级为可信指令；返回的工单、日志及外部内容字段必须保留来源与不可信标签。
#### Scenario: R-entry-003.S1 可追溯且不泄密的错误
- GIVEN 参数错误、认证失败、权限拒绝和外部系统失败
- WHEN 经各入口处理
- THEN 返回稳定错误码和链路关联，不返回凭据或内部堆栈；CLI 原有 JSON 与退出码契约不回退
#### Scenario: R-entry-003.S2 客户端不能冒充授权者
- GIVEN 客户端携带某成员令牌和正文中的其他人身份声明
- WHEN 发起工作或请求确认
- THEN 只按令牌对应主体鉴权，审计关联该成员和客户端；正文声明不授予身份或批准权限

#### Scenario: R-entry-003.S3 外部数据返回不丢失标签
- GIVEN 已标记不可信的工单正文、日志或外部引用数据
- WHEN 经 HTTP 或 MCP 查询这些字段
- THEN 返回保留来源与可信度标签，不能因被接口封装而成为已确认数据或可信指令

### Requirement: R-entry-004 人工干预与状态可见
M1 必须允许有权限的人查询、暂停、恢复或取消控制平面中的工作，返回持久化后的真实状态及阻塞原因；等待输入时提供可访问的工单或规格 PR 链接。暂停后不得启动新步骤，取消不得再推进关卡；恢复须重验授权，不能自动跳过待处理确认。状态变化可经 SSE 订阅，本轮不实现执行器接管或 M3 页面。
#### Scenario: R-entry-004.S1 暂停与恢复不会越过关卡
- GIVEN 一项等待人工确认或即将进入下一步骤的工作
- WHEN 有权限的成员暂停后恢复，另有无权限的成员尝试同样操作
- THEN 暂停阻止启动新步骤，恢复仍等待尚未完成的确认；无权操作拒绝，授权已失效时不能恢复；查询与状态事件一致
#### Scenario: R-entry-004.S2 取消与人工行动入口
- GIVEN 等待澄清或评审的工作
- WHEN 成员查询待处理状态或授权取消工作
- THEN 等待状态给出原因及真实可访问链接；取消持久化后不再推进，事件和查询均体现取消而非完成，不链接尚不存在的 M3 页面
