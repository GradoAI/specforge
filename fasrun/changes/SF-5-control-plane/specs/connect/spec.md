## ADDED Requirements

### Requirement: R-connect-001 GitHub 接入与边界
只有具接入管理权限的主体可配置 GitHub App 接入及仓库到组织、团队、项目的归属。外部长期凭据只在接入网关边界内加密保存，主密钥不与密文同存数据库，支持轮换且不返回秘密明文。connect 处理外部通信；工作、计划及关卡业务状态由控制平面维护，内部调用经双向 TLS 认证并受权限约束。不能把未授权仓库或未验证外部身份映射到已有工作。M1 必须在专用验证环境验证真实 GitHub 接入，模拟回归不替代该证据。
#### Scenario: R-connect-001.S1 授权仓库接入
- GIVEN 管理员配置一个 GitHub App 可访问且已归属团队与项目的仓库
- WHEN 读取该仓库工单并提交控制平面处理
- THEN 外部对象携带稳定来源标识与归属；控制平面维护工作状态；接入方不能自行确认关卡
#### Scenario: R-connect-001.S2 越界接入被拒绝
- GIVEN 无接入管理权限的成员、未配置归属的仓库或没有有效内部服务身份的调用
- WHEN 修改接入、请求受理或调用内部接口
- THEN 拒绝相应操作并保留可审计原因，不改变工作及关卡状态
#### Scenario: R-connect-001.S3 凭据隔离与轮换
- GIVEN 接入已保存测试凭据且管理员发起轮换
- WHEN 查询配置、检查持久化数据及日志，并用新凭据访问适配器
- THEN 配置与日志不返回秘密，数据库不保存明文凭据或其主密钥；新凭据生效，旧凭据不再被接入使用

#### Scenario: R-connect-001.S4 专用环境真实接入
- GIVEN 专用验证环境中已授权的真实 GitHub App、仓库、验证账号及真实控制平面
- WHEN 读取验证工单、写回、创建规格 PR 并同步有权限人的当前提交评审与合并事实
- THEN 保存可核对的真实外部对象标识及链接、同步和写回结果；与模拟适配器的回归证据分开记录，不将模拟响应作为真实接入通过证据

### Requirement: R-connect-002 可靠收件箱与对账
收到 GitHub webhook 须验证来源签名，按投递标识持久化收件箱；写入成功才应答，重复投递忽略，业务处理可重试。每 15 分钟按更新时间对账相关工单、PR 与评审，补齐遗漏事件；恢复后也可触发同样对账。webhook 尚未启用时须支持仅靠对账完成 M1 链路。对账与 webhook 重叠或乱序不能重复创建工作、丢失状态变更或回退较新的状态。
#### Scenario: R-connect-002.S1 验签与持久应答
- GIVEN 有效和无效签名的 webhook，以及收件箱存储暂时失败
- WHEN 接收事件
- THEN 无效签名被拒绝；持久化失败不返回成功确认；已持久化事件即使异步处理进程重启仍可继续处理
#### Scenario: R-connect-002.S2 重复及乱序交付
- GIVEN 同一事件被重复投递，且旧事件晚于新事件到达
- WHEN 收件箱和对账分别处理这些事件
- THEN 同一逻辑请求至多创建一项工作和一条接收确认；较新外部状态不会被旧事件覆盖
#### Scenario: R-connect-002.S3 对账补漏
- GIVEN webhook 未启用或漏掉工单、PR 与评审变化
- WHEN 到达 15 分钟对账周期，或恢复后触发对账
- THEN 相关遗漏变化被拉取并处理，与已接收事件去重；失败可追踪并重试，不能把未拉取结果标作已同步

### Requirement: R-connect-003 幂等写回与结果可追溯
受理成功须在来源工单确认一次并说明工作内容，后续只在需要人行动、获得结果或无法完成时写回。外部动作具有稳定幂等标识，待发送动作与对应业务变更同事务持久化；暂时失败可重试且不重复外部可见消息。写回失败不伪报成功，工作可查询待发送、失败及已送达结果；无需处理、取消及失败按真实结果表达。
#### Scenario: R-connect-003.S1 一次受理一次确认
- GIVEN 一个有权限的明确工单请求及其重复事件
- WHEN 工作成功受理并多次重试确认写回
- THEN 工单只出现一条接收确认且关联同一工作，不连续发送过程性进度消息
#### Scenario: R-connect-003.S2 提交及投递故障
- GIVEN 业务变更时进程重启，或 GitHub 已接受消息但响应丢失
- WHEN 恢复并重新投递待发送动作
- THEN 不丢失已提交的动作，也不重复外部可见消息；最终结果及外部对象标识可查询
#### Scenario: R-connect-003.S3 外部失败如实呈现
- GIVEN GitHub 暂时不可达或拒绝写回
- WHEN 工作有需告知的结论
- THEN 保留未送达或失败状态和可重试原因，不将其报告为已送达；恢复后按同一动作标识继续

### Requirement: R-connect-004 规格 PR 与评审事实同步
规格 PR 必须关联工作、规格层和提交版本；GitHub 评审、撤销、关闭、合并及新提交通过收件箱与对账同步为事实，由控制平面依据成员映射、权限和当前版本决定关卡。批准旧提交、已撤销批准、未经授权主体或 bot 的评论不能确认当前规格；确认与合并状态分别保留，不能用评论文字冒充 GitHub 事实。M1 不自动批准或合并规格 PR。
#### Scenario: R-connect-004.S1 当前版本评审
- GIVEN 关联到工作和规格层的 PR，以及有对应权限的人类评审人
- WHEN 当前提交获得有效评审并同步
- THEN 控制平面收到含评审人、提交版本及来源的事实，依据该层规则判定；接入方不会自行越过关卡
#### Scenario: R-connect-004.S2 旧评审失效
- GIVEN PR 已有批准，随后新增提交或批准被撤销
- WHEN 同步最新 PR 和评审状态，包括重复与乱序事件
- THEN 当前版本不能沿用过期批准；关闭未合并、批准及合并状态分别可查，旧事件不能恢复失效批准
#### Scenario: R-connect-004.S3 外部文字不是批准
- GIVEN bot、未关联账号或无权限成员在工单或 PR 评论中声称已批准或已合并
- WHEN 处理该评论
- THEN 内容仅作不可信数据，不能改变规格确认或合并事实，不触发自动批准与合并
